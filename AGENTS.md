# Agent rules

## Scope and authority

This standalone project must not inspect, import or copy other repositories or old RISEx/Radar material.

Only five files govern work: AGENTS.md defines process/safety; SYSTEM_SPEC.md defines current behavior; STATUS.md records accepted state/blockers; NEXT_TASK.md defines the finite objective, authority and acceptance; README.md documents operation. Git preserves history. Do not add governance/history files or treat historical permissions as current authority.

Follow current explicit owner instructions within system/tool restrictions. Complete authorized work with reasonable implementation choices. Ask only for materially missing information or genuinely new authority; do not invent approval gates for routine edits, setup, tests or Git operations. Record material policy/authority changes in NEXT_TASK before using them.

## Ownership and implementation

Work alone by default, as the owner currently requests. The same agent may implement, test, review and integrate; call this self-review, never independent review. Delegate only when explicitly requested. If delegation is requested, assign a fresh bounded session, non-overlapping ownership and a named isolated branch; preserve predecessor work before transferring ownership. Keep one integration owner. Delegates do not merge/push main or spawn further agents without authority.

Preserve the user's model/effort/speed settings. Do not change global settings, buy credits/resets or enable auto-reload. Report settings only from client evidence; unknown is not verified. Account usage is not task cost.

Specify outcomes and constraints, not a mandatory architecture. Implement the smallest coherent correction. No unrelated cleanup, frameworks, managers, infrastructure campaigns, platform migration, new markets or strategy tuning. Deferred work is not an acceptance prerequisite. No LLM belongs in the market loop; deterministic finite execution and required transport heartbeats are separate from agent management.

## Safety and secrets

Default to offline/paper work. New public collection needs a prospective NEXT_TASK gate. Agent Mainnet/testnet actions require the owner's concrete authorization recorded there; an affirmative reply to a concise proposal is sufficient, without a repeated fixed checklist. Do not ask again for the same authorized action and its necessary reconciliation/cancellation. Completion, cancellation, a materially different action or unclear intent requires new authority. Historical runs never authorize replay.

No withdrawals, transfers, unrelated account-wide cancellation, leverage/margin-setting changes, blind replay of ambiguous writes or hidden strategy changes. Policy, sizes, minimum exemptions, fee schedules, timing/resource limits and result semantics change only with explicit owner authority. Official/observed contradictions must be surfaced, not silently waived. Required safety fields are strict; irrelevant additive inbound fields are tolerated.

API credentials may pass through the private owner/assigned-agent conversation or approved protected local credential boundary. Mask by default; return the same credential privately only if the owner explicitly requests it. Store only in the approved protected store and retain only as needed. Never put secrets in Git, project files, arguments, environment variables, process titles, fixtures, journals, reports, captures, durable tool output, public shares or unassigned-agent messages. Seed phrases, recovery material and withdrawal credentials are prohibited. No plaintext fallback.

Preserve exact quantities, causal timestamps, identity, no-reuse and reconciliation. Acceptance is not a fill; unknown is neither no-fill nor flat. Open inventory, closed execution PnL, fee completeness and funding are distinct. Profit or fill-count targets never weaken validity checks. Preserve evidence and stop an unsafe action or unreliable calculation immediately; correct a bounded defect within scope without stopping unrelated safe development.

## Verification and acceptance

Before edits verify repository root, named branch, accepted base/HEAD and working changes. Bind checks to actual imports, source/configuration and inputs. Review the full actual diff and relevant surroundings. A defect report identifies candidate, violated contract, location, counterexample, impact and necessary verification; taste alone is not a defect.

Arithmetic, positions, execution, causal ordering or result-preservation changes require adverse regressions, relevant integration checks and one final clean isolated Python 3.11 full suite. Compute expected numbers independently of the helper under test. Preserve credential, funding, no-replay and exact-flat regressions. Low-impact changes need focused checks; docs-only changes need consistency/scope/identity review. Changed code invalidates affected checks; unchanged integration or docs-only commits need no duplicate suite.

Passing tests alone is not acceptance. Review evidence provenance, adverse behavior and scope. Record failures honestly; do not mask failures with skips or fix unrelated legacy code. A correction round needs a newly understood cause and finite verification; repeated failure without new diagnosis is a blocker. Preserve formally rejected candidates immutably; start corrections from accepted main. No force-push or history rewriting.

## Git, evidence and recovery

Stage only owned paths. Do not reset, stash, commit or overwrite another writer's work. Integrate only verified changes; verify remote main before claiming publication. Preserve worktrees, branches, patches and outputs, including unaccepted ones. Routine authorized implementation, local commits, evidence preservation and accepted integration/publication need no repeated approval.

Original inputs, manifests and historical claims are immutable. Stream large JSONL. New evidence uses separate versioned owner-only directories outside Git. A missing terminal is incomplete, never zero profit or success. Evidence must remain interpretable without a live tool cell. Batch material STATUS/NEXT_TASK updates; do not create ceremonial history commits.

After compaction recover objective/authority, branch/diff, actual imports, completed checks, remaining work and process ownership from current files/Git/evidence. Compaction alone does not require a new session. If recovery conflicts, preserve WIP_NOT_ACCEPTED or READY_FOR_REVIEW with honest DONE/NOT_RUN checks and request a handoff. Stop predecessor writes before transfer; never merge WIP merely to rotate. A handoff names versions/paths, unachieved objective, invariants, evidence, uncertainties, next action and process owner.

## Communication

Use concise Russian with the owner and English in these five files. Lead with result, evidence, limitations and next action. Do not invent costs, context percentages, URLs or future callbacks. Use native task cards only when actually assigning/transferring work; absence of a card is not a reason to duplicate tasks. Delegates must deliver results to the owner agent, or preserve a local packet and state that delivery failed.

No management heartbeat, encouragement loop, endless goal or periodic agent polling. Act on assignments, concrete blockers/results or completion events. A new campaign, hypothesis or real execution needs a new owner decision. Frozen modules stay frozen unless NEXT_TASK explicitly reopens them.
